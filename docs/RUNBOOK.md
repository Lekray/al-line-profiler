# RUNBOOK — построчный профайлер C/AL, утренний прогон

Инструкция на утро. Читать сверху вниз, ничего наизусть помнить не нужно.

Всё лежит в `scripts\` в корне репозитория. Только Windows PowerShell 5.1
(`powershell.exe`, не `pwsh`).

---

## 1. Одна кнопка

Открыть **консоль от имени администратора** (Пуск → Windows PowerShell → правой
кнопкой → «Запуск от имени администратора») и выполнить:

```
cd <корень репозитория>\scripts
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Profiling.ps1
```

Дальше скрипт всё делает сам и один раз просит человека: **выполнить сценарий в
клиенте NAV и нажать Enter**. По окончании отчёт открывается в браузере, а машина
возвращается в то состояние, в каком была.

По умолчанию отчёт строится по `Codeunit 80 Sales-Post`. Другой объект:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Profiling.ps1 -ObjectType 5 -ObjectId 90
```

Типы: `1` Table, `3` Report, `5` Codeunit, `6` XMLport, `8` Page, `9` Query.

Имя базы скрипты берут из переменной окружения `LP_DATABASE`, а если её нет — `NAV`.
Если стенд назван иначе, задать один раз на сессию:

```
$env:LP_DATABASE = '<имя базы>'
```

### Если прав администратора нет

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Profiling.ps1 -Mode Lite
```

Режим `Lite` ничего не включает и ничего не перезапускает: читает события 705
(«долгий SQL»), которые платформа пишет сама. Точности до строки кода он не даёт —
только запросы, их время и таблицы.

## 2. Что должно быть на экране

Семь шагов, каждый со своим вердиктом:

```
=== ШАГ 1/7  Проверка среды =========================================
  [ОК]   машина готова
=== ШАГ 2/7  Служба инстанции =======================================
  MicrosoftDynamicsNavServer$DynamicsNAV110: Stopped -> запускаем (в конце вернём в Stopped)
  [ОК]   ... запущена
=== ШАГ 3/7  Дамп исходников C/AL ===================================
  [ОК]   дамп обновлён, нумерация строк соответствует текущей компиляции
=== ШАГ 4/7  Сбор трассировки (нужен человек) =======================
        ПЛАН ИЗМЕНЕНИЙ  ... (что меняем и как вернём)
        ТРАССИРОВКА ВКЛЮЧЕНА -> выполнить сценарий, нажать Enter
  [ОК]   трассировка собрана
=== ШАГ 5/7  Построение отчёта ======================================
  [ОК]   отчёт: ...\out\run-<дата>\5_80.html
=== ШАГ 6/7  Откат ==================================================
  [ОК]   ... остановлена — как было до прогона
=== ШАГ 7/7  Отчёт ==================================================
  [ОК]   открыт в браузере
```

Признаки хорошего прогона в итогах шага 4:

| Строка | Что должно быть |
|--------|-----------------|
| `Событий:` | сотни тысяч и больше; в разбивке по ролям есть `ALStatement` |
| `Потеряно:` | `0` |
| `Кольцо:` | заметно меньше лимита, «первое событие через 0,0 с» |
| `Откат` | сессия остановлена, флаг возвращён, служба вернулась в исходное состояние |

Итоговая таблица прогона: все строки `ОК`, внизу «Прогон завершён».

## 3. Если не сошлось

| Симптом | Причина | Что делать |
|---------|---------|------------|
| `Нужны права администратора`, код 2 | консоль не поднята | перезапустить консоль от администратора; либо `-Mode Lite` |
| `Событий: 0`, код 8 | инстанция не перезапускалась после включения флага, либо сценарий не выполнял код C/AL | повторить прогон; убедиться, что сценарий действительно шёл в NAV |
| `Потеряно: кольцо перезаписало начало` | сценарий длиннее, чем влезло в кольцо | повторить с `-MaxSizeMB 4096` либо сократить сценарий |
| `ядро сообщило о потерянных буферах` | буферов не хватает на поток событий | `Collect-AlTrace.ps1 -BufferSizeKB 2048 -MaxBuffers 128` |
| `Не удалось создать сессию ETW`, код 7 | имя сессии занято хвостом прошлого прогона | `logman stop LineProfiler-AL -ets`, затем повторить |
| `Провайдер ETW ... не зарегистрирован`, код 3 | на машине нет сервера NAV | прогон возможен только там, где стоит NST |
| `не найден CustomSettings.config`, код 6 | инстанция названа иначе | `-ServerInstance <имя>` или `-NavServicePath <путь к Service>` |
| Номера строк в отчёте «не бьются» с кодом | объект перекомпилировали после дампа | повторить прогон без `-SkipDump` |
| Прогон убит жёстко (закрыли окно, перезагрузка) | откат не отработал | выполнить `out\run-<дата>\restore.cmd` **от администратора** |

### Проверить, что на машине ничего не осталось

```
logman query -ets | findstr /i LineProfiler
Get-Service MicrosoftDynamicsNavServer$DynamicsNAV110
findstr /i EnableFullALFunctionTracing "C:\Program Files\Microsoft Dynamics NAV\110\Service\Instances\DynamicsNAV110\CustomSettings.config"
```

Ожидаемо: сессии нет; служба в том состоянии, в каком была до прогона; флаг `false`
(или отсутствует).

## 4. Что прогон меняет на машине

| Что | Как возвращается |
|-----|------------------|
| эфемерная сессия ETW `LineProfiler-AL` | `logman stop ... -ets` в блоке `finally` — и при ошибке, и при Ctrl+C |
| `EnableFullALFunctionTracing` в `CustomSettings.config` | исходное значение из байтовой копии; копия рядом, `CustomSettings.config.bak` |
| служба инстанции (старт/перезапуск) | исходное состояние `Running`/`Stopped` |

Постоянный канал журнала `Microsoft-DynamicsNAV-Server/Debug` **не трогается вообще**:
сессия живёт только в памяти. Настройки ETW в реестре не меняются.

## 5. Файлы прогона

Каталог `out\run-<дата-время>\` в корне репозитория:

| Файл | Что внутри |
|------|-----------|
| `<тип>_<номер>.html` | отчёт: листинг объекта с платформенной нумерацией строк |
| `events.tsv` | события трассировки построчно (`ObjectType`, `ObjectId`, `FunctionName`, `LineNumber`, `Statement`, ...) |
| `trace.etl` | сырая трасса; перечитать без повторного сбора: `Collect-AlTrace.ps1 -ParseFile <файл>` |
| `slowsql.tsv` | режим `Lite`: формы запросов, отсортированные по суммарному времени |
| `manifest.tsv` | разобранный манифест провайдера: какие события и с какими полями умеет платформа |
| `collect.log` | пошаговый журнал сбора, включая сверку имён полей payload |
| `restore.cmd` | аварийный откат, если процесс убили |
| `CustomSettings.config.bak` | байтовая копия конфигурации до правки |

Дамп исходников — общий, лежит в `.alsrc\` (вне git), обновляется на шаге 3.

## 6. Что помнить про цифры

- **Трассировка искажает ранжирование.** Цена события примерно постоянна на оператор,
  поэтому дешёвые операторы в горячих циклах раздуваются пропорционально числу вызовов.
  Всегда смотреть время рядом с числом вызовов.
- **Цену события можно измерить**: `Start-Profiling.ps1 -Calibrate` прогоняет сценарий
  дважды (сначала без трассировки, потом с ней) и делит разность на число событий.
  Сценарий во втором прогоне должен быть **тем же**, иначе цифра бессмысленна.
- **Номера строк верны только для той компиляции**, с которой снят дамп. Перекомпилировали
  объект — прогон повторить.
- **Событие пишется на каждый оператор всей инстанции**, а не только вашей сессии.
  Чем короче сценарий и чем меньше посторонней активности, тем чище замер.

## 7. Ручной режим, если нужен только кусок

```
# только проверка среды, ничего не меняет
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-TraceEnvironment.ps1

# только сбор (из консоли администратора)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-AlTrace.ps1 -Mode Full

# только долгие SQL за последний час, без прав
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-AlTrace.ps1 -Mode Lite -Minutes 60

# перечитать уже собранный .etl
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-AlTrace.ps1 -ParseFile .\out\run-<дата>\trace.etl

# только отчёт по объекту, без трассировки
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-Report.ps1 -ObjectType 5 -ObjectId 80 -Open
```

Справка по любому скрипту: `Get-Help .\Collect-AlTrace.ps1 -Full`.
